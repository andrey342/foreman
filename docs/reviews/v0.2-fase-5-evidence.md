**Fallo encontrado y corregido durante el trabajo:** la primera versión de `setupCommand` decidía a qué clave iba cada respuesta comparando la pregunta con un objeto recién creado (`q === deliveryQuestion(…)`, siempre falso), así que la respuesta de entrega habría acabado en `isolation`. Ahora cada pregunta lleva su clave; el test de submódulos lo cubre con respuestas que distinguen («Merge it here» y «In this checkout as it is» → `{ delivery: { mode: "merge" }, isolation: "none" }`).

### `claudeExe` (D-132)

El plan pedía `claudeExe` editable con `$.config.set`. La sonda de esta fase mostró que una opción `userConfig` de un plugin no es una fila de `/config`, así que `$.config.set` no la alcanza. En su lugar:

- `/foreman setup --claude-exe <ruta>` la guarda en `$.store` si el archivo existe y `<ruta> --version` sale con 0. Vale para todas las sesiones y repos, al momento y en cada arranque de sesión, por encima del ajuste del plugin.
- `--claude-exe ""` vuelve al ajuste del plugin (o a `claude` del PATH).
- `--claude-exe` sin valor dice cuál se usa. Antes abría el diálogo de setup; corregido.

Tests: «setup --claude-exe: a path that answers --version is kept…» (ruta inexistente, `--version` con exit 1, ruta buena, `status` ejecuta `agents` con esa ruta, limpiar) y «the claude set from the chat holds from the session start over the plugin setting» (con `options.claudeExe` del plugin).

### Quinta herramienta `foreman_setup`

El §7 dice «foreman, set up this repo», pero el modelo del chat no puede escribir un comando de barra. Por eso hay una herramienta `foreman_setup` (entrada `show`). D-75 lista cuatro herramientas; esta es la quinta. Va en D-132 y en el CIERRE como decisión a confirmar. Test: «criterion 4: five tools in the prompt's list (setup since Phase 5, D-132)» y el de `--show` por la herramienta.
